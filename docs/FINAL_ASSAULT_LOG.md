# 마지막 총공세 작업 기록

22단계까지 만든 보안 Agent 앱(`on-client`)을 내 PC에서 매일 쓰는 앱으로 다듬는 기록입니다.
확인한 것만 적고, 확인하지 못한 것은 그대로 「확인 불가」로 적습니다.

## 작전 선택

- 화면 틀: 관제 대시보드형 (상태 카드 + 조회 기록)
- 포장 형태: 포장 없이 내 PC에서 실행 (`npm run package-app` 하지 않음)

## 핵심 기능 3가지

1. **내 PC 점검** — 이번에 새로 만든 대시보드 (아래 1일차·2일차)
2. **업무 앱 접근 판정** — 14단계 `renderDecision`
3. **보안 기록과 AI 설명** — 15·18단계 `renderEvents`·`renderExplanation`

2·3번은 이미 판정 환경에서 통과한 기능이며, 이후 일차에서 안내 문구와 화면을 다듬습니다.

## 1일차 — 기존 프로젝트 다시 실행

- 기존 저장소를 그대로 사용(새 폴더로 옮기지 않음). 마지막 커밋 `6b37109`(22단계 재현 기록) 위에서 시작.
- `npm run check`(문법 확인) 통과, `node src/server.mjs --demo` 로 `http://127.0.0.1:5189` 실행 확인.
- 이 확인은 Linux 환경의 예제(--demo) 실행입니다. Windows PC에서의 실행은 학생 PC에서 다시 확인해야 합니다.

## 2일차 — 「내 PC 점검」 대시보드 구현 (`on-client/student/extension.mjs`)

보호 현황의 「보안 상태·알림·진단」 칸 맨 위에 붙였습니다.

| 부분 | 내용 |
|---|---|
| 요약 한 줄 | `실측 n/5 · 확인 불가 m개 · 주의 k개 · 측정 시각`. 조회 전·조회 중·실패·지원 없음·오래됨(1분 초과)을 서로 다른 문장과 색으로 구분 |
| 다음 행동 | 「내 PC 다시 조회」 버튼. 누를 때만 `api.get('/api/pc/status')` 한 번 호출, 진행 중 중복 호출 막음, 자동 반복 없음 |
| 상태 카드 5개 | CPU·메모리·디스크 남은 공간·Windows 방화벽·Windows 기록. ●정상 범위 / ▲주의 / ?확인 불가를 기호와 글자로 표시(색만으로 구분하지 않음), 사용률은 `<meter>` 막대 |
| 근거와 한계(펼치기) | 항목마다 "이 값만으로 말할 수 없는 것"과 출처. "주의 0개는 안전이 아님"을 명시 |
| 조회 기록(펼치기) | 조회할 때마다 시각·결과를 위로 쌓음(최대 10건, 메모리에만 두고 저장·전송하지 않음) |

지킨 규칙

- 읽지 못한 항목은 정상으로 바꾸지 않고 「확인 불가」와 이유(권한 없음·시간 초과·이 OS에서 읽지 않음 등)를 표시.
- 실패하면 이전 값을 현재 값처럼 남기지 않음(이전 결과는 조회 기록에만 남음).
- 화면 글자는 `textContent` 로만 넣음, `innerHTML`·`style` 속성 사용 안 함(앱 CSP 준수). 제공 CSS 클래스(`card`, `grid-2`, `kv`, `state`, `tag`, `btn`)만 사용.
- 앱이 칸을 다시 그려도 펼침 상태와 버튼 초점을 되살림.
- 주의 기준(내가 정함): CPU 90% 이상, 메모리 90% 이상, 디스크 남은 공간 10% 미만, 방화벽 프로필 하나라도 꺼짐. Windows 기록 건수는 판정하지 않음.

확인한 것 (Linux, --demo, 헤드리스 Chrome)

- 조회 전 → 버튼 → 실측 3/5(CPU·메모리·디스크) · 확인 불가 2개(방화벽·Windows 기록: 이 OS에서 읽지 않음) 표시
- Tab으로 버튼·펼치기 이동, Enter로 조회와 펼치기 작동, 조회 뒤 초점이 버튼으로 돌아옴
- 서버가 500 실패를 돌려주면 "조회에 실패했습니다(코드)"와 모든 값 확인 불가 표시

아직 확인하지 못한 것

- Windows PC에서 방화벽·Windows 기록 실측 → 학생 PC에서 확인 필요
- 화면 낭독기(NVDA), 200% 확대
- 처음 보는 사람 사용성 관찰(4일차)

### 2일차 추가 — 직전 조회 대비 추이

제공 기능(`src/pc-status.mjs`)은 그대로 두고, 중복 측정 없이 조회 기록의 **직전 OK 값**과 현재 값을 비교하는 기능을 `student/extension.mjs`에 더했습니다.

- CPU·메모리·디스크의 증감을 `%p`(백분율 포인트)와 ▲/▼/= 로 표시하고, 직전 값의 **측정 시각**을 함께 적음.
- 재측정하지 않음(이미 받은 값만 비교, 일반 권한). 현재 값이나 직전 값이 '확인 불가'면 숫자를 지어내지 않고 **'비교 불가'와 이유** 표시.
- 조회 기록에 `disk` 값 저장을 추가(이미 cpu·memory는 저장 중이었음). 기존 기능·제공 파일은 변경하지 않음.
- 화살표는 증감 방향만 뜻하며 좋음·나쁨 판정이 아님을 안내문으로 명시.

확인: 문법(`node --check`) 통과, DOM 목으로 렌더 통과(조회 전 안내문 표시), 추이 계산 단위 테스트 통과(현재/직전 비교, 확인 불가 정직 처리). Windows PC에서 두 번 조회해 실측 증감 표시는 학생 PC에서 확인 필요.

## 5일차(일부) — 화면 다듬기와 실행 안내

처음 보는 사람 관찰(4일차) 전에, 화면을 직접 캡처해 보며 눈에 띄는 문제부터 고쳤습니다.

| 문제 | 고친 내용 |
|---|---|
| 모든 학생 칸에서 라벨과 값이 붙어 보임(「안내앱을 골라…」) | 공통 함수 `row()` 에 제공 CSS `.kv`(라벨 칸 + 값 칸)를 함께 적용 |
| 「내 계정」 칸이 90px 좁은 격자에 갇혀 한 글자씩 꺾임 | `renderIdentity` 바깥 상자 이름이 제공 CSS의 `.identity` 와 겹쳐서 생긴 문제 → `identity-panel` 로 이름 변경 |
| 업무 앱 판정 뒤 무엇을 해야 할지 안 보임 | 허용·거부·추가 확인·확인 불가·요청 실패마다 「다음에 할 일」 한 줄 추가 |
| 판정·기록 시각이 `2026-10-30T17:35:00Z` 처럼 읽기 어려움 | 한국 시각으로 바꾸고 원래 값은 괄호로 남김 |
| 보안 기록 걸러 보기 칸이 붙어 있고, 상세 버튼이 기본 모양 | 제공 `.row` 간격과 `.btn` 버튼 모양 적용, 결과 0건이면 「전체로 바꿔 보세요」 안내 |

- 실행 안내 `docs/FINAL_RUN_GUIDE.md` 작성(Windows·Mac 실행 방법, 화면에서 볼 것, 주의할 점).
- 확인: Linux 예제 실행에서 세 메뉴 화면 캡처, 화면 폭 390px에서 가로 스크롤 없음, 페이지 오류 없음.
